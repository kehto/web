# napplet/evil follow-ups (kehto/web#381): summary

Suite: `napplet/evil` @ `6df4cd1` (fresh clone, prebuilt `napplets/*/index.html` only, no build scripts, no installs).
Spec: NIP-5D `nostr-protocol/nips#2303` @ `f60550c` (silent on referrers, base URLs and resource hints); CSP3 ED
`w3c/webappsec-csp` @ `e3461f7` (prefetch/prerender initiators use `default-src`; preconnect uses the union of source
lists). Engines: Chromium 147.0.7727.15, Firefox 148.0.2, WebKit 26.4 (Playwright 1.59.1 builds).

## Done

- Embedding URL: `denyNappletReferrer`, `renderNappletReferrerPolicyMeta`, `renderNappletHostBase` in `@kehto/shell`,
  warn-once in `observeFrame`, wired into Paja and the e2e harness. The `document.baseURI` leak (full host URL,
  query included) was worse than the referrer one; only a host-page `<base>` closes it. WebKit ignores the iframe
  `referrerpolicy` for srcdoc, so the host meta is the portable control.
- Resource hints: `evil-02`'s logged requests were blocked `rel=prefetch` attempts (CSP violation console lines).
  The real channels are `rel=prerender` (Chromium GET), `preconnect` (Chromium DNS+TCP, WebKit TCP) and
  `dns-prefetch` (Chromium and Firefox DNS), none governed by any host control. Closed by the opt-in
  `resourceHintLock` (shared Trusted Types policy, attribute-writer pins, host byte scan); Paja couples it to its
  nested-context decision.
- XSLT: `XSLTProcessor.transformToFragment` minted an iframe under the shipped `nestedContextLock` in all three
  engines. Both locks now remove it; the frame battery has an XSLT vector.
- Tripwire: event-driven `nested-context` revocation under the lock (load + bound-port envelopes, no polling).
- Opt-in runner `tests/e2e/evil-suite.spec.ts` (`KEHTO_EVIL_SUITE_DIR`, `KEHTO_EVIL_SUITE_LOCK`, `KEHTO_EVIL_SUITE_OUT`).
- Reruns with a locally patched scratch copy of the suite (NAP-STORAGE method names; window-level `postParent` and
  `evil.ping` neutered). Kehto was not patched.
