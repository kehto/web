# Quick 261120-l10: end a cancelled CVM request in the shell (kehto/web#510)

Spec: NAP-CVM draft napplet/naps#31, head re-resolved 2026-11-20 = `28cf1bdb5c6412bfbfcecb79a5a5121e18376f2f`
(unchanged). Message handling: "`notifications/cancelled` may refer only to this napplet's
requests"; ids are mapped only if the shell "consistently maps request references such as
cancellation". Error Handling: "exactly one corresponding `.result` with the same envelope `id`".
Timeouts: duration runs "from receipt through queueing, initialization, consent, payment";
"A late response MUST NOT produce a second result or be redelivered as `cvm.event`."
MCP 2025-11-25 cancellation: the sender "SHOULD ignore any response to the request that arrives
afterward". No NAP-CVM error names a locally cancelled request.

## Decisions
- Cancel bypasses admission (`operations.run(..., { admit: false })`): tracked, own deadline,
  still ended by close/teardown.
- Queued / pending-approval target: aborted locally, never published, no approval for the cancel.
- Dispatched target: approval, then `CvmTransport.cancel()` (#509), then abort locally (also
  covers a transport still initializing: `cancel()` false, signal aborts before send).
- Target settles with `session closed` (spec-gap decision), before the cancel's ack.
- Repeat cancel of a request already being cancelled: ack, nothing published.
- Cancel publication fails: cancel gets the error, target keeps running.
- Mock: no unsettled requests, so docs-only. No conformance case: the runner awaits each
  envelope, and the error code is a Kehto decision, not NAP text.
