# Summary: signer changes push identity.changed, reload only for re-injection

Root cause: two reloads. `browser-host-signer.ts` called `state.reload()` whenever a signer reached
`connected`, and the adapter's signer subscription called the host environment callback (which
always reloaded) after every Blossom upload identity refresh, plus whenever webrtc/dm availability
flipped. The bridge already pushed `identity.changed`, but the frame was gone by then.

Fix: no reload in the signer controller; the environment callback reloads only when the advertised
domain change touches the active frame's declared/admitted domains. `identity.changed` is
deduplicated by last published pubkey.

Known gaps: background runtime tabs are not reloaded on any environment change (unchanged).
