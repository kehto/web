# Plan: Paja pushes identity.changed instead of reloading on signer change

1. Find every reload a signer change causes: `createHostSignerController` reloaded on every
   `connected` status; the adapter's environment callback reloaded after every upload identity
   refresh and on webrtc/dm availability flips.
2. Drop the signer-controller reload. Gate the environment callback: diff the advertised domain set
   (`buildShellCapabilities`) and reload the active frame only when an added domain was declared by
   the napplet (or it declared none) or a removed domain was admitted (NIP-5D fixed injection).
3. Push `identity.changed` only on a real pubkey change (no duplicate `""` for `connecting`).
4. Tests: unit tests for the gate; enable and extend the `paja-identity.spec.ts` fixme (connect,
   switch, disconnect, same generation); `paja-webrtc.spec.ts` proves the narrow reload still
   happens; the single-window fixture re-runs identity-dependent work on `identity.changed`.
5. Docs (`docs/packages/paja.md`, `packages/paja/README.md`) and a `@kehto/paja` patch changeset.
