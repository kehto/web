# Quick Task 261031-l9b: admit @napplet 0.35.x/0.36.x in @kehto/* peer ranges (#364)

## Problem
Published `@kehto/*` packages declare `@napplet/core`/`@napplet/nap` peers `>=0.32.0 <0.35.0`.
The llm domain first ships in `@napplet/core@0.35.0` / `@napplet/nap@0.35.0`, and the latest
`@napplet/nap@0.35.1` depends on `@napplet/core@^0.36.0`. npm ERESOLVEs, pnpm warns.

## Facts checked
- Kehto does not import llm from `@napplet/*`; it mirrors draft types in `packages/services/src/llm-types.ts`.
- core 0.35.0 adds the `llm` NapDomain + Llm* types (additive); core 0.36.0 adds `NAP_IMPLEMENTATIONS`
  metadata/selection helpers (additive). nap 0.35.x adds `./llm` subpath.

## Tasks
1. Verify kehto against core 0.36.0 + nap 0.35.1 (temporary, uncommitted pnpm override):
   build, type-check, unit tests; type-level assignability of kehto llm mirror vs published `@napplet/nap/llm/types`.
2. Widen peers: `@napplet/core` → `>=0.32.0 <0.37.0`, `@napplet/nap` → `>=0.32.0 <0.36.0` in every
   published package (acl, cli, firewall, paja, runtime, services, shell). Keep baseline dev pins (0.32.x).
3. Update guards (`tests/unit/napplet-package-alignment.test.ts`, `tests/unit/sdk-migration-guard.test.ts`)
   and docs that state the peer range; patch changesets for affected packages.
4. Gates: build, type-check, test:unit, docs:check, aislop; push and open PR closing #364.
