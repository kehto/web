# INC endpoint identifiers instead of manifest d tags

Issue claim, verified on `origin/main` b29e2a70 with a failing unit test ported from the issue's Node repro
(`packages/runtime/src/inc-endpoint-identity.test.ts`, 10 of 11 failing before the fix): two live sessions sharing a
`d` tag emit the same `sender`, a session with `dTag: ""` is dropped on emit, and `inc.channel.open` to a shared
`d` tag fails as `target not found`.

## Spec check (before design)

- Authority: `napplet/naps` master `377bf939c6c906817084b43dd21d424de646dbc2`, `naps/NAP-INC.md`. Byte-identical to
  the ref the issue cites (`19de5ce1cea40cd4c76089cdd8126e9f87648049`); last NAP-INC commit is `f4545b1f` (#104).
  No open `napplet/naps` PR touches NAP-INC (checked the open PR list on 2026-11-20).
- Schemas: `target`, `sender`, `peer` are runtime-assigned, opaque, unique per live endpoint, "MUST NOT be interpreted
  as a manifest `d` tag", bound to the authenticated endpoint including manifests without a `d` tag, never reused in a
  runtime session. A channel stays bound to the endpoint authorized at open; replacement needs a new channel.
- Discovery: there is no peers/presence message. Callers get identifiers "from runtime-attested INC events or an
  explicit runtime-authorized peer selection".
- Packaged contract `@napplet/nap@0.40.0` `inc/types`: field shapes match. Only comments lag (`sender`/`target`/
  open-result `peer` described as napplet identity). Upstream wording drift, no local type needed.

## Decisions

1. Identifier lives in the runtime INC module, bound to the frozen `SessionEntry` of one registration, minted lazily
   from `hooks.crypto.randomUUID`, tracked in an issued set so a repeating UUID source fails closed instead of sharing.
   Not `SessionEntry.instanceId`: that is host-supplied and may survive a re-registration.
2. `d` tag targets are retired, not kept as a warned fallback. The NAP forbids interpreting a target as a `d` tag, and
   a fallback would let a napplet address a peer by public name. Rejected as `target not found` (no liveness oracle)
   plus a once-per-runtime host diagnostic `KEHTO_INC_DTAG_TARGET_RETIRED`.
3. Registry `onRegister` (replacement) and `onRetire` now retire the INC endpoint: channels close as
   `peer destroyed`, subscriptions drop, identifier is forgotten but stays reserved.
4. New host API `Runtime.getIncEndpointId(windowId)` is the "runtime-authorized peer selection" boundary.
5. ACL, firewall, and permission keys stay principal-keyed (`dTag` + hash). `SessionRegistry.getWindowIdByDTag`
   stays as a host-side lookup; the runtime no longer uses it.
