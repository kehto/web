# Quick 261120-r03: closed on WebRTC revocation, mock/service parity after close (kehto/web#503)

Spec: NAP-WEBRTC draft napplet/naps#59, head re-resolved 2026-11-20 = `fb4dd6f0e6294e1837733d2af61931e3e114bd97`
(unchanged). Error Handling: "The shell SHOULD send a `webrtc.event` with `type: "closed"` when an
established session ends because a peer disconnects, ICE fails, signaling expires, or policy
revokes the capability." Wire Protocol: "it MUST NOT deliver messages for an unknown `sessionId`".
Shell Behavior: "The shell MUST respond to every request with a result message carrying the same
`id`." Errors list both `session not found` and `session closed` without saying when each applies.

## Decisions
- Revocation (`onPermissionRevoked`, ACL block via `onCapabilityRevoked(null)`) sends `closed`
  (reason `policy denied`, as the mock already did) per live session, then forgets it. Destroy
  and unregister stay silent. `closed` is a shell session event, not a peer message, so the
  "enforce per-napplet policy before ... delivering peer messages" MUST does not block it.
- After a session ends, send/sendBytes/close answer `session not found` in both the service and
  the mock (an ended session is unknown; no tombstones). The mock changes, not the service.
- Requests in flight at revocation still get a result; an open awaiting approval gets
  `policy denied`.
