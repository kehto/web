# Keep large relay plans approvable within one Firewall request

8865f73d52a4864afee145f28d26520476273927, NAP-RELAY PR #2 @

## Decision
Keep the Firewall's 128-requirement cap (DoS/abuse bound; plans are napplet-steered through
authors, third-party NIP-65 lists and hints). Bound plans to one approval instead: one batch of
at most 127 origins chosen by author coverage (deterministic, hints last), the rest reported as
`incomplete`. Rejected: multi-batch approval (several prompts, unbounded grant growth, nested
revocation), collapse-on-default-allow (no aggregate scope; the cap throws before rules run),
exempting host lists (plans are not host-bounded).

## Tasks
1. Failing repros: 200-origin subscribe/query under default allow, one malformed URL among good
   ones, publish with 200 required inboxes, 200 paths on one origin.
2. Export MAX_PERMISSION_REQUIREMENTS from @kehto/firewall (re-export from @kehto/runtime).
3. Services: coverage-aware `resolvePlan`, `capturePlan` bound for any router, per-origin
   requirements, `incomplete` for a lost author, `too many relays` for unfittable required
   publish relays, strip host-only `partial` from resolveRelays.
4. Runtime relay.* and COUNT: per-origin requirements; over-cap plans get `too many relays` /
   `too-expensive`, never a denial. CVM: napplet relays capped at 32, host planners use host
   defaults, so it cannot reach the cap; left unchanged.
5. Shell prompt: one "contact N origins" row per mediated operation with exact origins listed.
6. Docs, changeset, gates (build, type-check, unit, docs, aislop, Playwright), PR into staging.
