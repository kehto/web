# Summary

`kehto paja --target-url` now opens a development document that lists `resource` under `napplet-requires`. Paja loads the fetched `index.html` as a network-isolated snapshot: no dev origin in the CSP, no host-injected base URL, the same closed policy as a local single-file target. `window.napplet.resource` is exposed with direct network denied, which is what NAP-RESOURCE PR 80 at `ae5b9c64ab8a4d8909f288829a01e99d6bd713bc` requires.

- `packages/paja/src/target-network.ts`: pure `planTargetNetwork` and `findExternalAssetReferences`, shared by server, CLI and browser host.
- `packages/paja/src/browser-target-frame.ts`: target-url branch picks the snapshot when `resource` is required; an incompatible `resource` error now explains itself.
- `packages/paja/src/server.ts`, `cli.ts`, `browser-target-diagnostics.ts`: `/__kehto/target-network.json`, `PajaServer.inspectTargetNetwork()`, CLI startup notice, message-log and console diagnostics; the CORS probe is skipped for a snapshot.
- `@kehto/shell` is unchanged: `admitBrowserDocument` still refuses required `resource` with any direct origin and omits optional `resource` from a direct-network frame.

## Decisions a maintainer may want to overrule

- The switch is automatic on `napplet-requires resource`, not a flag. A live frame can never satisfy that requirement, so the alternative was a guaranteed refusal.
- A module-graph dev server (unbundled Vite) that requires `resource` now renders a snapshot whose URL-referenced scripts are blocked, with the CLI and message log naming them, where it used to render an admission error.
- No opt-in to expose `resource` to a live frame was added; the spec forbids it.
