# Answer legacy Firewall drops in ungated domains on their NAP wires (kehto/web#494)

Scope: when the legacy Firewall gate drops a defined request in a domain ACL
does not gate, `createDenialResponse` fell through to the generic
`<type>.error`, which none of those NAPs define. `catalog/acl-denial` could not
see it because it denies through ACL.

## Refs (re-resolved 2026-11-20)

- NAP-COMMON #67 `8cd0eae8`, NAP-LISTS #68 `7cf00cdb`, NAP-SERIAL #61
  `0c6e88ab`, NAP-BLE #62 `b46b8691`, NAP-WEBRTC #59 `fb4dd6f0`, NAP-LINK #53
  `100e5c93`, NAP-GAMEPAD #130 `0b28f77e`, NAP-IDENTITY master `377bf939`.

## Decisions

- Rows in `policy-denials.ts` for every napplet request of common, lists,
  serial, ble, webrtc, link and gamepad.
- Identity needs no row: both gates answer it first with its runtime-owned
  safe default (`createCanonicalDomainResult`); pinned by a regression test.
- Spec gaps: `common.getProfile` `pubkey` (hex target or `''`),
  `common.follows` `pubkeys: []`, `lists` `error: "policy-denied"` + `reason`,
  `gamepad.subscribe` → `"blocked"` snapshot.
- Conformance: new `catalog/firewall-denial` driven through an optional
  `TargetSession.openLegacyFirewall()`. The Kehto target boots a scoped session
  without `permissions` and with a blocking legacy Firewall; since
  `admitBrowserDocument` requires `permissions`, that session loads probes the
  way a legacy host does (identity bound at hello, exported shell APIs only).
