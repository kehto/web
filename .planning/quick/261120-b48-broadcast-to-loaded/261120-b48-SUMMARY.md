# Summary: shell pushes reach napplets from napplet.hello

Root cause: `nip5d-transport.ts` called `registerSourceSession` only from `dispatchEnvelope`, so a
window's runtime session and frozen environment (the inputs every shell push reads) existed only
after its first NAP envelope. A napplet that only listened never got `theme.changed`,
`identity.changed` or service broadcasts.

Fix: `bindPort` registers the source session right after the first valid `napplet.hello` binds the
port. Eligibility (exposed domain, current ACL, live bound port) is unchanged; revoke, port close,
second hello and windowId replacement still remove the target.

Push sites audited:
- `ShellBridge.publishTheme` / `publishIdentityChanged`: fixed.
- `ServiceRuntimeContext.listWindowIds` / `sendToEligibleNapplet` consumers (theme service,
  intent service `intent.changed`, mocks): fixed by the same registration.
- `injectEvent`, `gamepad.state`: gated on a napplet subscription, not applicable.
- Proxy `emit()`, `audio-manager`, Paja `browser-intent-host`: post straight to the bound port, no
  session dependency.

Out of scope: the `test.fixme` in `tests/e2e/paja-identity.spec.ts` stays; Paja reloads the frame on
signer change instead of pushing, which is a separate Paja gap.
