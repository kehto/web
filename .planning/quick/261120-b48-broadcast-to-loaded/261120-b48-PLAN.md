# Plan: shell pushes reach napplets from napplet.hello, not their first message

1. Register the source session (verified identity + frozen environment) in `bindPort`, right after
   the first valid `napplet.hello` binds the port, instead of lazily in `dispatchEnvelope`.
2. Audit every shell-initiated push for the same dependency: `ShellBridge.publishTheme` /
   `publishIdentityChanged` (session + environment), runtime `ServiceRuntimeContext.listWindowIds` /
   `sendToEligibleNapplet` (theme-service, intent-service `intent.changed`, gamepad `gamepad.state`,
   mocks), and `isDomainAllowed`. All read the session registry / environments, so the single
   bind-time registration covers them. Proxy `emit()` helpers and `audio-manager` post straight to
   the bound port and never depended on a session.
3. Unit tests in `@kehto/shell` (fake + real MessageChannel): hello-only delivery with and without
   shell, service broadcast, `onNip5dIframeCreate` at hello, eligibility, no-identity, teardown on
   host revoke / port close / second hello, windowId replacement.
4. Acceptance: `kehto conformance --profile full --domain theme --domain identity` with
   `catalog/broadcast-to-loaded` unchanged; drop it from `KNOWN_KEHTO_FINDINGS`.
5. Docs (`docs/packages/shell.md`, `packages/shell/README.md`) and a `@kehto/shell` patch changeset.
