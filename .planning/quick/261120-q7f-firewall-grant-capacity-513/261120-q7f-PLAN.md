# Finish the Firewall grant-capacity work from #517

Based on `staging/issue-sweep-2611` after #517. No NIP-5D or NAP text sets a grant
table size; the table is host policy (#336). Per-domain non-denial codes were checked
against each owning NAP head (refs in `packages/services/src/approval-failure.ts` and
`policy-denials.ts`).

## Tasks
1. Every `authorizeOperation` caller maps `capacity` / `busy` / `unavailable` to its
   NAP's closest non-denial code, with a recorded spec-gap reason where none exists.
2. A default-rule `allow` writes no grant: approve, consume, continuation and
   `stillGranted` consult the rule live; only rule-open scopes reach a prompt.
   `RuntimePermissions.rulesChanged()` closes live operations and rechecks frames.
   `DEFAULT_RULE_GRANT_PREFIX` / `isRuleGrant` deprecated (`DEFAULT_RULE_GRANTS`).
3. `maxGrantsPerPrincipal` (default 512, Paja `firewall.maxGrantsPerNapplet`) and
   `admitPermissionGrants`: evict oldest session grants (own, then largest holder),
   never persistent or once, never ones the same request relies on.
4. Tests, docs, changesets, gates, Playwright, PR into staging.
