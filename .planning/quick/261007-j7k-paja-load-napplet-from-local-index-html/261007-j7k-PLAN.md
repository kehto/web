# Paja: load a napplet from a local index.html

## Context
Paja can currently open a napplet in two ways. It resolves an `naddr`/`nevent` from relays and Blossom (runtime-pointer mode), or it proxies a dev server through the CLI's `--target-url` (iframe-url mode). There is no way to open a napplet from an `index.html` file on disk. A developer with a single-file build (for example vite-plugin-singlefile output) has to publish it or run a dev server first. The goal is to add a file picker and drag-and-drop to Paja's runtime-pointer UI that opens a local `index.html` in a new runtime tab. It would use the same srcdoc, prelude, CSP and sandbox path that resolved pointers already use.

## Approach

### 1. Local target type and builder (new `packages/paja/src/local-target.ts`)
- Define `PajaLocalTarget`:
  - `source: 'local'`
  - `fileName`
  - `dTag`
  - `aggregateHash`
  - `indexHtml`
  - `relays: []`
  - `blossomServers: []`
- Add `createPajaLocalTarget(file: File | { name: string; text: string })`. It:
  - Reads the text and computes the sha256 of the bytes with `@noble/hashes`, which `@kehto/nip` already uses.
  - Sets `aggregateHash = computeAggregateHash([{ path: '/index.html', sha256 }])`, reusing `packages/nip/src/5a/index.ts:55`. The identity is a real NIP-5A hash over the local bytes, so editing the file gives it a new identity.
  - Sets `dTag` to `<meta name="napplet-dtag">` if present, otherwise `local-<slugified filename stem>`.
  - Rejects files that are not `.html`/`text/html` and empty files.
- Define `PajaRuntimeTarget = PajaResolvedPointer | PajaLocalTarget` with an `isLocalTarget()` guard.

### 2. Widen the frame and tab plumbing to accept either target
- `browser-target-frame.ts`:
  - Switch `navigateFrame`, `getTargetIdentity` and `getTargetOriginIdentity` from `PajaResolvedPointer` to `PajaRuntimeTarget`. They only read `dTag`, `aggregateHash`, `indexHtml`, `relays` and `blossomServers`, so no logic changes.
  - Local targets go through the existing runtime-pointer branch: register → setEnvironment → `injectNappletNamespacePrelude(injectPajaRuntimeCsp(...))`, under the same sandbox.
- `browser-runtime-tabs.ts`:
  - Change the types of `PajaRuntimeTab.resolvedTarget`, `addRuntimeTab`, `resolvedTargetKey` and `resolvedTargetTitle`.
  - A local tab's title is the file name, and its key is `local:<dTag>:<aggregateHash>`.
  - A local tab gets `pointerValue = ''`, so `snapshotRuntimeTabs` already leaves it out of persistence, which is what we want: the file cannot be re-read after a reload.
  - `bindRuntimeTabBlossomServers` and `createPajaShareUrl` should skip local targets.
- **Do not** call `runtime.catalog.install()` for local targets. The installed catalog stays limited to verified artifacts, which is enforced by `installed-napplet-catalog.ts` and the guard at `tests/unit/nip5d-conformance-guard.test.ts:444`.

### 3. Loader entry point (`browser-host.ts`)
- Add `loadLocalFile(state, context, file)` next to `loadRuntimePointer` (`browser-host.ts:401`). It:
  - Calls `createPajaLocalTarget`.
  - Logs `paja.local.load` / `paja.local.loaded` / `paja.local.error` via `appendPajaMessageLog`.
  - Reuses the duplicate dialog when the key matches.
  - Calls `addRuntimeTab`.
- Expose it as `state.loadLocalFile(file)`, the same way `state.loadPointer` is exposed.

### 4. UI (`host-page.ts` + `browser-host.ts` wiring)
- In `renderPointerControls` (`host-page.ts:296`), add a hidden `<input type="file" id="runtime-local-file" accept=".html,text/html">` and an "Open file…" button next to Load.
- Change the empty stage text to "Load a napplet pointer or drop an index.html to start a runtime tab."
- Wire the following next to the pointer-form handler (`browser-host.ts:345`):
  - The button clicks the hidden input. On `change`, it calls `state.loadLocalFile(files[0])` and then resets the input value.
  - Add `dragover`/`dragleave`/`drop` on `#napplet-stage` (and the empty stage). `dragover` gets `preventDefault` and toggles a `.drop-active` class. `drop` loads the first `.html` file.
- Add a minimal `.drop-active` outline style in the existing host-page CSS.
- Only runtime-pointer mode gets this UI. iframe-url mode is unchanged.

### 5. Known limitation (document it, don't solve it now)
srcdoc has no base URL, so relative `<script src>`, CSS and images in a local file will not load. Only self-contained, single-file HTML is supported. Loading a folder or zip and mapping assets is a possible follow-up. State this in the UI's status line on error and in the docs.

## NAP / NIP-5D check (do this first during execution)
Per AGENTS.md, check NIP-5D and NAP-SHELL (`napplet/naps` master) for frame identity and loading requirements, and record the ref in the PR. Expected result:
- Conformant: the injected prelude and `window.napplet.shell` are unchanged.
- The local, unsigned identity is a Paja dev-host decision outside the spec's resolution path. Document it in a source comment and in `docs/policies/NIP-5D-CONFORMANCE.md`, next to the existing `dev-target` convention.

## Verification
- Unit tests:
  - `local-target.test.ts`: the hash matches `computeAggregateHash` for known bytes, the dTag is derived from the meta tag or filename, non-HTML and empty files are rejected.
  - `host-page.test.ts`: the file input and button render only in runtime-pointer mode.
  - `browser-runtime-tabs.test.ts`: a local tab is excluded from the snapshot, and the key and title are right.
  - `browser-host.test.ts`: `loadLocalFile` adds a tab, does not touch the catalog, and sets srcdoc with the prelude and CSP.
- Run `pnpm build && pnpm type-check && pnpm test:unit && pnpm docs:check`, then the aislop gate.
- Manual: `kehto paja` in runtime-pointer mode, then pick or drop one of the built single-file napplets. Confirm it boots, `shell.ready` and `shell.init` appear in the message log, and the tab title is the file name. Reload the page and confirm the local tab is not restored.
