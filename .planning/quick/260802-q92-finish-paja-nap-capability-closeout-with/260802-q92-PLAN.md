# Quick Task 260802-q92: Finish Paja NAP capability closeout

## Goal

Make every NAP domain advertised by Paja genuinely functional through a real
browser, network, signer, storage, or host backend; retain deterministic fakes only
as explicit test fixtures that cannot justify capability advertisement. Replace
browser-native confirmations with a serialized accessible HTML dialog and prove
real backend effects through unit and browser tests.

## Protocol authority

Validate affected behavior against the exact active `napplet/naps` draft heads,
including NAP-RELAY `0be8abce18beb46ca37bd4ddd042f58d30b4eedc`,
NAP-KEYS `cecb64257e0ac29926bb746832a477c553ab307c`, NAP-OUTBOX
`4589a8f9a16d8aa29b3740e2b3b0cdca11e0976e`, NAP-UPLOAD
`a7cc17463cbf5d9cb87884b31071bc4fc826034c`, NAP-LINK
`e25143355f6d416bfce73b12ec814f1c795ec16a`, NAP-DM
`a0a48588b3c9caca9540cccec19635b85231a00f`, NAP-FS
`b640cf337c0481f0f9a0216c00843f797a5c6df6`, and the complete immutable
authority map in `260802-q92-IMPLEMENTATION-AUDIT.md`. NIP-5D
`eb45dfd7335b7f88cb53781984c553581d2b4c34` governs namespace presence and
transport. Hyprgate is an implementation reference only; its product-specific
window management and policy machinery are out of scope.

## Must-haves

- Paja renders one accessible, serialized in-page confirmation surface for sign,
  publish, and upload requests; no Paja path calls `window.confirm`.
- Confirmation details preserve the upload consent information required by
  NAP-UPLOAD, default safely to denial, and do not lose concurrent requests.
- `keys.forward` executes the forwarded unbound hotkey in the Paja host simulator,
  while mapped actions remain governed by the existing NAP-KEYS runtime behavior.
- `link.open` performs a safe `http(s)` external handoff, reports denial for an
  unsafe protocol or host-policy rejection, and reports `opened` once the shell has
  accepted and handed the request to the user agent as required by NAP-LINK.
- Relay, outbox, upload, storage, identity, keys, config, resource, theme, notify,
  media, intent, count, link, common, lists, serial, BLE, WebRTC, CVM, INC, DM,
  FS, and the mandatory shell handshake have real backends and automated
  behavioral coverage.
- Canned constants, local echoes, no-op mutations, unconditional grants, and
  in-memory session maps are gaps even when their envelopes satisfy the wire type.
- Capability discovery omits a domain whenever its required real backend is absent
  or unavailable in the current browser/runtime environment.
- `@kehto/*` workspace dependencies and installed `@napplet/*` versions match the
  current manifests/lockfile; no unrelated dependency churn is introduced.
- Package documentation and a changeset describe the shipped Paja behavior.

## Tasks

1. Implement the Paja host interaction gaps test-first.
   - Add an async serialized confirmation controller with approve/deny, Escape,
     focus restoration, and clear sign/publish/upload content.
   - Thread async consent through signer, relay/outbox, and upload call sites.
   - Implement safe external-link opening and forwarded-hotkey dispatch using the
     bounded patterns that fit Paja's single-window simulator.

2. Audit and replace simulated advertised-domain backends.
   - Trace every advertised domain from `shell.init` through its service handler to
     a real side effect, permission boundary, lifecycle, cleanup, and error path.
   - Replace the canned COMMON/LISTS/CVM/NOTIFY behavior and unsafe RESOURCE policy
     with real Nostr/browser/host integrations.
   - Replace the serial, BLE, and WebRTC memory controllers with Web Serial, Web
     Bluetooth, and RTCPeerConnection plus Nostr signaling implementations.
   - Make optional capability advertisement depend on actual backend availability.

3. Prove real effects rather than response envelopes.
   - Use injectable browser/network boundaries for unit tests, reserving fakes for
     explicit test mode only.
   - Extend Paja Playwright coverage to exercise browser-visible or transport-visible
     effects, permission denial, disconnect/cleanup, and unavailable-backend omission.
   - Keep the HTML consent and host-action regressions from the first iteration.

4. Synchronize release artifacts and validate the whole repository.
   - Update Paja docs and add the appropriate changeset.
   - Run focused tests, Paja Playwright specs, build, type-check, full unit tests,
     docs checks, and the pinned AI-slop gate.
   - Commit atomically, push the branch, and open a PR recording specification refs,
     conformance, verification output, and intentionally out-of-scope Hyprgate code.
