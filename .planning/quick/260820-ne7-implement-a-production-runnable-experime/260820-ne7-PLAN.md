# Quick Task 260820-ne7: Implement the production-runnable experimental IPC shell

## Objective

Turn `@kehto/shell-ipc` from a production carrier/runtime library accompanied by a
proof program into a supported, production-runnable experimental shell. Ship one
public process-host API and one npm executable that launch and own arbitrary raw
napplet processes over the existing Unix-socket NIP-5D projection, while retaining
host-bound registration, carrier-neutral NAP behavior, and the absence of a
napplet-side interface.

Before the first NAP-touching edit, recheck NAP-SHELL and NAP-INC at
`napplet/naps` `origin/master@c0f7dd14460622fc3a9870ea57a538474cf776fa`.
That authority requires bare ready, one init, host-bound identity, and pre-ready
gating, but defines no IPC carrier. The implementation is conformant to those NAP
lifecycle rules and intentionally remains an experimental carrier spec gap.

## Locked decisions

- **D-01:** Add public `launchIpcShellHost` and a packaged `kehto-ipc-shell` executable.
- **D-02:** The CLI is `kehto-ipc-shell --host ./host-config.mjs -- <executable> [...argv]`; accept no command string and always spawn with `shell:false`.
- **D-03:** The trusted ESM host module exports `createIpcShellHostConfig()` and supplies immutable registration plus `Omit<RuntimeAdapter, 'sendToNapplet'>`, allowing real deployment-owned services, persistence, signer, relay, consent, and policy implementations.
- **D-04:** Inject only `KEHTO_IPC_SOCKET_PATH` as projection-owned child environment state; never inject registration identity/environment and never ship a napplet helper or injected interface.
- **D-05:** Preserve numeric child exit codes; map actual signal termination to `128 + os.constants.signals[signal]`, including SIGKILL after grace-timeout escalation.
- **D-06:** One idempotent lifecycle owns the child, projection/endpoint, runtime composition, signal listeners, timer, escalation, structured result, and cleanup.
- **D-07:** Keep the current reference host explicitly proof-only, make it a thin consumer/configuration of the production boundary, and remove the flaky cross-process stdout ordering oracle.
- **D-08:** Add no Tauri, Electron, `postMessage`, browser/interface injection, or napplet-side helper; do not modify `packages/runtime/src` or `packages/shell/src`.
- **D-09:** Keep code, tests, docs, package/bin metadata, the existing shell-ipc changeset, full verification, explicit-path commits, push, and PR #236 synchronized. Preserve and never stage the user-owned root `package.json` modification.
- **D-10:** Loss of the current already-ready projection peer is terminal for the process host: observe it after projection teardown, enter the one lifecycle gate, request SIGTERM, escalate after the bounded grace period when needed, preserve the actual child-derived status, and report `peer-disconnected`; pre-ready, stale, and host-initiated peer closes do not produce this observation.
- **D-11:** Shell-owned CLI usage, error, and diagnostic text must not reveal registration/environment secrets or the caller base, generated private directory, or endpoint path. The raw child necessarily receives `KEHTO_IPC_SOCKET_PATH`; inherited stdout/stderr is child-controlled application output and must pass through without filtering or rewriting, so a child may disclose its own environment/path outside the shell-owned redaction guarantee.

## Interfaces

The executor should create and export these contracts from `@kehto/shell-ipc` without
changing the existing projection overloads:

- `IpcShellHostCommand`: non-empty `file`, readonly string `args`, optional `cwd`, and optional readonly environment map.
- `IpcShellHostOptions`: existing transport controls plus host registration,
  `Omit<RuntimeAdapter, 'sendToNapplet'>`, command, and optional non-negative safe
  integer `shutdownGraceMs`.
- `IpcShellHostConfig`: the host options without `command`, returned synchronously or
  asynchronously by a named `createIpcShellHostConfig` ESM export.
- `IpcShellHostExit`: `status`, numeric child code or null, signal or null, and one
  reason distinguishing numeric exit, exact `independent-child-signal`, explicit close,
  forwarded host signal, current-ready-peer disconnect, and shutdown-timeout escalation.
- `IpcShellHost`: frozen registration, child PID, public Runtime, host-only endpoint
  path, `waitForExit()`, and idempotent `close()`; both terminal methods join the same
  cleanup/result promise.
- `launchIpcShellHost(options): Promise<IpcShellHost>`.

`launchIpcShellHost` may compose a projection-local no-op `sendToNapplet` member solely
to satisfy the existing `createIpcShellProjection` adapter input; the projection's
already-tested targeted egress replaces it. Do not broaden the public host config back
to a full `RuntimeAdapter`, and do not change `packages/runtime/src` to accommodate it.
Extend the local projection options with a synchronous, observation-only
`onPeerDisconnected(registration)` callback. It fires exactly once only when the
transport reports loss of the record's current connection after that connection had
completed bare ready and after its runtime session teardown; explicit endpoint/
composition close, pre-ready loss, and stale generations do not fire it. The process
host consumes this callback directly rather than watching `SessionRegistry` or
constructing another transport.

## Threat model

### Trust boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv -> child process | User-controlled executable and argv cross into OS process creation; shell interpretation must never occur. |
| Trusted host config -> runtime/projection | Deployment code supplies authoritative registration, services, persistence, signer, relay, consent, and policy; registration still passes existing clone/freeze validation. |
| Raw child -> Unix socket/runtime | Peer frames are untrusted and retain existing RFC 7464 bounds, identity-claim rejection, bare-ready gate, capability/ACL checks, and targeted egress. |
| OS signal -> host lifecycle -> child | Process-global signals can race child exit/close; exactly one terminal gate must forward/escalate and restore listeners. |

### STRIDE register
