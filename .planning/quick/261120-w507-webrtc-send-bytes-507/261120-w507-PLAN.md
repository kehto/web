# Implement NAP-WEBRTC sendBytes byte payloads in the reference service and Paja

Spec authority: NAP-WEBRTC PR #59 @ fb4dd6f0e6294e1837733d2af61931e3e114bd97 (re-resolved
2026-11-20, still the head): Byte payloads, Limits, Error Handling.

## Tasks
1. Services: canonical padded base64 codec (`encodeWebrtcBytes` / `decodeWebrtcBytes`); a
   `sendBytes` hook routed through the shared session action (lifecycle, revocation, destroy);
   `invalid request` for non-canonical text, `payload too large` over `maxPayloadBytes`
   (sendBytes decoded, send serialized); `unsupported` without the hook; drop non-canonical
   peer bytes events.
2. Parity with `@kehto/mocks`: lifecycle parity test gains sendBytes steps and bytes events;
   codec vectors agree with `mockCanonicalBase64Length`.
3. Paja default controller: binary data-channel send, `binaryType = 'arraybuffer'`, ArrayBuffer
   -> `bytes` event, strings stay `message`, report `maxPayloadBytes`. soy-rtc/1 stays JSON-only
   (`unsupported`), guarded by a unit test.
4. Conformance: Kehto target supports sendBytes; fixture adds a non-canonical case.
5. Two-Paja Playwright spec over a real data channel; docs, changeset, gates, PR.
