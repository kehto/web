# Paja: detect "zero relays connected" and say so

Incident (2026-11-02): Firefox WebSocket starvation from many open tabs made
every `wss://` relay connection fail at once; two napplets "randomly" stopped
loading. Paja showed a generic pointer timeout, so it looked like a napplet or
deploy bug and had to be diagnosed from the browser console.

Change: pointer resolution tracks per-relay connection outcomes alongside the
manifest query (nostr-tools `ensureRelay` is idempotent, so no extra sockets).
Zero connected -> `PajaRelayUnreachableError` (`relay-unreachable`) with an
actionable message (offline / blocked / browser WebSocket limit), surfaced as
the pointer status and a `paja.relay.unreachable` log entry, even when the
deadline expires first. Partial connectivity keeps the existing messages (now
with the connected count); pools without `ensureRelay` are unchanged.

Scope: pointer resolution (the incident's surface). The live relay backend's
connected-count indicator is a possible follow-up, not this task.
