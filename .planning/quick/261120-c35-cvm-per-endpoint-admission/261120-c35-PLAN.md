# CVM per-endpoint request admission (kehto/web#355)

Scope: bound in-flight NAP-CVM work per authenticated endpoint at the service
boundary, with a bounded queue, a deadline that runs from receipt, complete slot
release, and Paja wiring. Audit session and relay-hold retention separately.

## Contracts and decisions

- NAP-CVM draft napplet/naps#31, head re-resolved at
  `28cf1bdb5c6412bfbfcecb79a5a5121e18376f2f` (unchanged from the issue).
  Security Considerations: shells SHOULD apply per-napplet concurrency limits.
  Timeouts: the accepted duration runs from receipt through queueing, consent,
  and the final response; expiry is `relay timeout`. Sessions: `close` completes
  pending operations with `session closed` before acknowledging.
- Spec gap: the error table has no load-shedding entry. Overflow reuses
  `policy denied` (shell policy), which is also how a busy approval budget
  already surfaces for this domain. No new error string.
- What main already had: the approval coordinator serializes identical-scope
  operations and caps pending work at one shared `maxPending` (64) for every
  napplet and domain. Neither is a per-napplet budget, and hosts without a
  permission adapter have nothing. The rate limiter is a rate, not a
  concurrency bound. So admission is new, placed in `@kehto/services` where
  the deadline and the transport call already live; no `runtime.ts` edit.
- Budget key: the authenticated endpoint (runtime window id), matching the
  draft's unit for sessions, correlations, and `close`. Two windows of one
  napplet are separate endpoints.
- Defaults: 8 running, 32 queued per endpoint. Paja's stricter existing
  bounds (startup burst 20, shared pending 64) stay in front of it.

## Tasks

1. `cvm-admission.ts` (slots and FIFO queue per owner) and `cvm-operations.ts`
   (deadline from receipt, abort reasons, release on every exit). Route
   `cvm.discover`, `cvm.request`, and `cvm.registry.*` through it.
2. Record a session when a request is handed to the transport (retention fix).
3. Paja: `simulation.cvm.concurrency` into both CVM wirings.
4. Tests: service, runtime boundary, Paja host unit, Paja browser flow.
5. Docs, changeset, gates, PR with the retention audit.
