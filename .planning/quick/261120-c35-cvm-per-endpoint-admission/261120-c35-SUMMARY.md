# CVM per-endpoint request admission

Branch `feat/355-cvm-request-admission`, closes kehto/web#355.

- `createCvmService({ concurrency: { maxInFlight, maxQueued } })`, defaults 8
  and 32 per endpoint. One slot per `cvm.discover`, `cvm.request`, or
  `cvm.registry.*` envelope from receipt to settlement. `cvm.close` is never
  queued.
- Deadline starts at receipt; queue and approval time are spent from it and the
  transport gets only the remainder. Queue expiry is `relay timeout` with no
  publication. Overflow is `policy denied` (documented spec gap).
- Slots return on result, error, deadline, `cvm.close` (pending and queued work
  for that server gets `session closed` first), approval cancellation,
  permission revocation, window destroy, unregistration, and dispose.
- Retention fix: sessions are recorded at hand-off to the transport, so a
  failed request no longer strands a transport session and relay hold.
- Paja reads `simulation.cvm.concurrency` in the plain and multiplayer wirings.
  The e2e harness host registers no CVM service, so there is nothing to wire.
- `@kehto/mocks` completes every request synchronously and does not model
  admission; noted in its decisions comment.
- `.planning/STATE.md` is left alone to avoid conflicts with parallel branches.

## Follow-ups (not in this change)

- Approval coordinator deadline (60 s default) ends a longer accepted CVM
  request with `policy denied`; NAP-CVM allows up to 300 s and names
  `relay timeout`.
- No cap on distinct server sessions one endpoint holds open; no idle expiry.
- The transport keys sessions by server pubkey only: relays are fixed by the
  first request, and later relay hints are approved but unused.
- Upstream: NAP-CVM has no error for shell load shedding.
