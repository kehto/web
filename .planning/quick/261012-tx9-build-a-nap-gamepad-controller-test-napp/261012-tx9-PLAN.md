# Controller tester

Authority: napplet/naps PR 108, commit 0b28f77e3dfa0f07dd7c0f9d61a7090ee99f3a5e, naps/NAP-GAMEPAD.md. Runtime authority implementation: Kehto PR 297, merged b89015f3. SDK 0.29.0 currently lacks the wrapper; use the shipped injected API directly, without inventing messages or a client. This is a draft-targeted runtime demo, not a claim that the SDK change has published.

1. Scaffold apps/gamepad-test using napplet create/init. Build a single-file controller inspector with full slot/index metadata, axes, analog buttons, focus/availability, snapshot count, and clear no-controller/unsupported states. No direct native access, network, storage, or relay. Close listeners on teardown.
2. Exercise the built artifact through real Kehto sandbox injection and service, including two-frame focus isolation, connection changes, denied native access, absent domain and blocked/unavailable state. Check 200x160, 320x560, 900x600, 2400x1200 in both themes. Provide a local Paja preview and hardware instructions.
3. Run build/type/unit/docs/browser/conformance and slop gates; commit by path and open a PR. No package changeset unless shipped package output changes.

Design: gamepad-test; one job: inspect shell-mediated controller snapshots. GAMEPAD required for controller testing; THEME optional with local dark fallback. No auth requirement, persistence, interop, or relay. Compact toolbar, scrollable full-frame controller grid; tiny views retain focus status and scrolling controls, wide views show multiple controllers and expanded axes/buttons. No minimum size or title masthead. Focus loss renders received neutral values, never synthesizes release actions. Snapshot values are diagnostic data, not a game action engine.
