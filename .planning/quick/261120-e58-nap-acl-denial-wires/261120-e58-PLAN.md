# Deny NAP requests on their own failure wires (kehto/web#458)

Scope: the shared ACL / legacy Firewall denial path (`createDenialResponse`) answered every domain without a special case with `${type}.error`. For CVM that's `cvm.request.error`, which NAP-CVM forbids. The same fallback produced invented `.error` types for relay, outbox, upload, count, notify, dm and fs.

## Contracts and decisions

- Authority: NAP-CVM draft napplet/naps#31 head `28cf1bdb5c6412bfbfcecb79a5a5121e18376f2f` (re-resolved before the PR, unchanged). Error Handling: "There are no `cvm.*.error` messages; ACL denial returns the matching `.result` with `error: "policy denied"`. On a shell error, success payload fields MUST be omitted." and "Truly unknown message types retain the silent-ignore behavior defined by NIP-5D."
- Other domains on the same path were checked against their open draft heads: RELAY #2 `9f30b350`, OUTBOX #32 `8865f73d`, UPLOAD #33 `f5cc981e`, COUNT #69 `9353a0c6`, NOTIFY #11 `67877ef6`, DM #74 `2c4e4423`, FS #88 `bd1b9e91`, CONFIG #14 `bed9cb5b`, KEYS #9 `8869a4cf`, MEDIA #10 `7806f438`, RESOURCE #80 `ae5b9c64`. None of them defines a `.error` message except RESOURCE.
- "Clear" means three things hold: the wire table lists `<op>.result` with `error?`, the error-handling text routes failures there, and no success field is required unless the NAP says what it holds on failure (e.g. `ok: false`).
- Chosen: an allowlisted per-type table (`packages/runtime/src/policy-denials.ts`) consulted before the generic fallback, used by both the runtime ACL path and the legacy Firewall gate. Types with no row keep today's behavior.
- The runtime reason passes through unless the NAP mandates a code (CVM `policy denied`) or enumerates one (COUNT `policy-denied` with the reason in `reason`, FS `policy-denied`).
- Requests whose NAP defines no reply (`relay.close`, `outbox.close`, `notify.dismiss`/`badge`/`channel.register`) are denied silently.
- Service side, same CVM sentence: `cvm.discover` failures no longer send `servers: []`, and `CvmDiscoverResultMessage.servers` is optional.
- Left as spec gaps (generic `.error` kept, listed in RUNTIME-SPEC.md): `upload.info`/`upload.status`, `outbox.resolveRelays`, `config.*`, `keys.*`, `media.*`, and unknown types outside `cvm`. `resource.*` stays on its NAP-defined `.error`.
- Consumers: `@kehto/shell`'s injected client already accepts both `.result` and `.error`. `@kehto/mocks` and Paja don't rely on the old shape. Packaged `@napplet/nap@0.41.0` cvm types declare no `.error` message, so there's no upstream drift.
