# Implement NAP-LLM across the kehto stack

Authority: napplet/naps PR #134 (`nap-llm`, head `3e10939cf788878bbdcc022c101f0ac6193f316c`, draft).
Packaged contract: `@napplet/nap@0.32.0` (installed) has no `llm` export. Upstream
napplet `feat/nap-llm` (`6e5c9fa93e522dde4c8e22a251190ededf43d357`, unpublished) defines
`LlmApi`/wire types; Kehto mirrors them locally in `@kehto/services` until the package
line publishes `@napplet/nap/llm`. Recorded as upstream drift, not a blocker.

Decisions
- Single ACL capability `llm:generate` gates every `llm.*` request; results and
  `llm.delta` map to the same recipient capability. ACL denial answers on the NAP
  result wire with `{ code: 'unsupported' }`.
- Tri-state interfaces: `llm` is advertised whenever the host runtime registers the
  service (runtime support), even with no provider configured. `llm.select` with no
  connections prompts the user to configure one (Paja opens the Language models panel)
  and answers `unsupported` until a connection exists. Shell exposes
  `getShellDomainState(hooks, domain)` → `supported | unconfigured | disabled` via a new
  optional `isConfigured()` adapter hook; Paja paints `unconfigured` toggles yellow with a
  warning glyph.
- Services own validation, handles, consent-before-submission, duplicate ids,
  cancellation, deadlines, delta ordering, safe errors. Hosts implement
  `LlmConnectionHost` (select/describe/authorize/generate). Pure wire mappers cover the
  three dominant provider protocols (OpenAI Chat Completions, Anthropic Messages, Google
  Gemini generateContent) plus `createHttpLlmProvider({ fetch })`; credentials travel only
  in the provider request header to the configured base URL.
- Paja stores connection metadata in plain localStorage and API keys only in an
  AES-GCM vault keyed by PBKDF2-SHA-256 (600k iterations) from a user password; keys are
  never logged, never sent to napplets, and only placed on the provider request.
  Per-generation consent is always asked (spec: stored key/selection is not authorization).

Tasks
1. `@kehto/acl`: `llm:generate` capability + `llmMap` + tests.
2. `@kehto/runtime`: `llm` domain handler/dispatch, unsupported fallback without a
   service, NAP-shaped ACL denial, tests.
3. `@kehto/services`: `llm-types.ts`, `llm-service.ts` (`createLlmService`,
   `LlmServiceError`), `llm-providers.ts` (mappers + HTTP provider), conformance tests
   LLM-C01..C11 subset, exports.
4. `@kehto/shell`: `llm` service-only domain, `LlmHooks`, `getShellDomainState`,
   prelude `window.napplet.llm` (select/describe/generate/cancel, deltas, abort), tests.
5. `@kehto/paja`: simulation/parity/CLI domain, `browser-llm-vault.ts` (crypto),
   `browser-llm-connections.ts` (store + host), `browser-llm-panel.ts` (sidebar UI,
   chooser, unlock), confirmation copy/log, tri-state interface toggles, adapter wiring,
   tests.
6. Playground: register an echo `llm` service fixture.
7. Docs: `docs/llm.md`, package docs/READMEs, NIP-5D conformance policy row, changesets
   (acl/runtime/shell/services/paja minor).
8. Gates: build, type-check, unit, docs:check, aislop; commit by path; push; PR.
