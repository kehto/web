# Paja settings panel: every tunable number becomes a persisted user default

User ask: "EVERY magic number should be a default that can be changed by the user,
and persisted between sessions. Requires a settings panel." Follow-up: audit all
numbers; PR targets the open staging PR (#459).

## Audit

`AUDIT-RAW.tsv` is the AST scan of every numeric literal (excluding 0/±1/2) in
`packages/paja/src/*.ts` (non-test). 443 hits, classified as:

1. **Tunables** (timeouts, intervals, waits, retry counts, query limits, display
   caps) -> registered settings.
2. **Abuse/DoS bounds** (byte caps, per-window counts, rate windows, seen-set sizes,
   field lengths) -> registered settings with hard min/max clamps so a guard cannot
   be disabled.
3. **Not settings** (allowlisted with reason in the guard test):
   - Nostr event kinds (wire contract) -> deduped into `nostr-kinds.ts`.
   - Crypto/format constants (salt/IV bytes, AES-256, key/pubkey lengths, storage
     format versions, base64 math, hex radix, randomBytes sizes).
   - RFC address ranges, HTTP status codes, magic-byte signatures, Game Boy header
     offsets, port/kind ranges (65535), regex group indexes, unit conversions
     (`/1000`), fixture timestamps.
   - Presentation (CSS, textarea rows, id abbreviation, percent, gamepad animation).
   - Security floors may only be raised: vault min password length (>=12), PBKDF2
     iterations (>=600k), distinct-char floor (>=4).

## NAP check

Draft refs (bleeding-edge policy): NAP-WEBRTC `fb4dd6f` (PR napplet/naps#59) —
shell MAY limit peers/rooms/payloads/labels, `maxPayloadBytes` advertised;
NAP-FS `bd1b9e9` (PR #88) — `FsLimits` are runtime-chosen and advertised;
NAP-RESOURCE `ae5b9c6` (PR #80) — caps are SHOULD with recommended values.
All limits are shell policy; advertised values must track the effective setting.

## Design

- `src/settings.ts` (environment-neutral): registry (key, group, label, help,
  default, min, max, unit, scope browser|server), `getPajaSetting(key)`,
  `normalizePajaSettings(raw)`, `setActivePajaSettings(values)`. Values read at
  call time so changes apply to new operations without a reload.
- `src/browser-settings.ts`: overrides stored at `kehto:paja:settings.v1`
  (overrides only; corrupt/out-of-range entries dropped; storage unavailable =>
  session-only with status), plus a `<dialog>` generated from the registry,
  opened from a header button, with per-field reset, reset-all, aria-invalid and
  role=status.
- Config file / raw options gain `settings: { key: number }` (validated). Server
  scope settings applied in the CLI/server process; browser scope settings seed
  the host config. Precedence: browser override > config file > built-in default.
- Exported constants keep their names/values as defaults.
