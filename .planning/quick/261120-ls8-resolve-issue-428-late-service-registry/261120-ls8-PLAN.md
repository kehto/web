# Resolve #428: late services advertised but not routed

Issue claim: `createRuntime` copies `hooks.services` once, Paja adds `webrtc` after a NIP-07 signer connects, so `shell.init` advertises a domain the runtime never routes and `webrtc.open` gets no reply. Proposed one-liner: alias the live object.

## Verified on main (b29e2a70)

- The copy is real and intended: `RuntimeAdapter.services` is documented as static initialization, and `registerService`/`unregisterService` own `onRegistered`, permission binding and pending-approval cancellation. Aliasing the host object would skip all of that for late handlers, leave `registeredServices` stale and make the runtime write into a host-owned object. Rejected.
- Paja's own path was already fixed by #442 (`trackPajaServices` registers through the runtime before frames reload; `tests/e2e/paja-webrtc.spec.ts` covers it). The issue predates that merge.
- The general defect remains for any shell host: advertisement reads `ShellAdapter.services`, routing reads the runtime's copy. Reproduced with a failing test: advertised `true`, handler calls `0`, replies `0`.

## Contracts checked

- NIP-5D, nostr-protocol/nips#2303 at `dskvr/nips@f60550c3409d6d81a875088ec83e660571e10504`: domain presence means available; "Messages with an unrecognized `type` MUST be silently ignored"; security note 6 ties that to preventing capability probing.
- NAP-SHELL, `napplet/naps@377bf939c6c906817084b43dd21d424de646dbc2`: the environment describes only exposed domains.
- NAP-WEBRTC draft PR #59 at `napplet/naps@fb4dd6f0e6294e1837733d2af61931e3e114bd97` (head rechecked): every request gets a result with the same `id` once the domain is exposed.

Decision: the wire stays silent for a domain with no handler (an error reply would answer probes). The conformance bug is advertising without routing, so fix that and give the host a diagnostic instead.
