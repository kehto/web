# Quick 261120-c04: map CVM cancellations, expire server requests (kehto/web#504)

Spec: NAP-CVM draft napplet/naps#31, head re-resolved 2026-11-20 = `28cf1bdb5c6412bfbfcecb79a5a5121e18376f2f`
(unchanged). Message handling: "For outgoing requests only, it MAY map IDs to unique transport
IDs if it restores the caller's ID in the returned MCP response and consistently maps request
references such as cancellation." "`notifications/cancelled` may refer only to this napplet's
requests." Sessions and events: "Server requests still require a response or expire under
session policy." Timeouts: default 30000, integer 1..300000.

## Decisions
- The service owns ownership (transport has no caller principal): an in-flight book per
  endpoint/server/typed id holds an opaque handle passed to `request()` as `execution.handle`.
- In-flight cancel -> optional `CvmTransport.cancel()` (Nostr transport maps requestId to its
  correlation id; settled -> false, nothing published). Legacy transports: publish unchanged,
  warn once `KEHTO_CVM_TRANSPORT_CANCEL` (tracked in docs/compatibility.md).
- Own settled request -> ack, not published. Foreign / missing requestId -> `invalid message`
  (spec-gap decision; not encoded as a conformance case).
- Server requests expire after `serverRequestTimeoutMs` (default 30000, 1..300000), lazily
  pruned on access. Mock matches on its scheduler.
