# Scope the approval deadline to the approval phase (kehto/web#457)

Scope: a `cvm.request` accepted with `timeoutMs: 120000` ended at 60 s with `policy denied`. The approval coordinator armed one 60 s timer per request and kept it running through `execute`; its expiry aborted the action and the CVM adapter mapped `cancelled` to `policy denied`. Reproduced on `staging/issue-sweep-2611` (`ffa9726b`) with `tests/unit/cvm-deadline-runtime.test.ts` through the real coordinator.

## Contracts and decisions

- Authority: NAP-CVM draft napplet/naps#31 head `28cf1bdb5c6412bfbfcecb79a5a5121e18376f2f` (re-resolved, unchanged). Timeouts: "The shell MUST enforce the accepted duration from receipt through queueing, initialization, consent, payment, and final response or publication." "Expiry returns `relay timeout`". Conformance: "A 120000 ms call returns after 45000 ms. | It succeeds if permitted by policy".
- The CVM service already owns that deadline (#456, `cvm-operations.ts`, started at receipt, passed to the coordinator as the request signal), so the coordinator needs no domain deadline.
- Chosen: the coordinator's `timeoutMs` and `maxPending` bound the approval phase only. At the point just before `execute`, the timer is cleared, the queue slot is returned and equivalent requests are released. The entry stays in `pending`, so `cancel`, `dispose`, revocation and the caller's signal still abort running work.
- Rejected: a domain-supplied deadline. It adds API surface, still leaves the coordinator's cap on the other domains (upload, fs pickers, serial, webrtc, intent), and is redundant for CVM.
- Found on the way: equivalent requests were chained on the earlier request's full settlement, so two concurrent `cvm.request`s to one server ran one after the other. That defeated #456's `maxInFlight`. They now chain on the decision only.
- Kept: the host approval-wait cap inside a longer CVM duration. An unanswered prompt is withdrawn at 60 s and the request answers `policy denied`; a napplet cannot extend a host prompt bound. Flagged for the maintainer.
- Domains whose action is now bounded only by its own logic and source lifetime: `intent.invoke` (target reply), `webrtc.open`, `upload.upload`, fs pickers, `serial.open`, media, `link.open`. LLM is not coordinated (its host `authorize`). Before this fix those were cut off at 60 s with their denial shape; master NAP-INTENT `377bf939` sets no timeout, and the other NAPs are drafts with no coordinator timing rule.
