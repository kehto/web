# Relay failures reach napplets as policy denied (kehto/web#460)

Scope: an approved `outbox.subscribe` closed with `policy denied` while the firewall had allowed everything and every relay connection was failing. The subscribe chain `planRead -> authorizeOperation -> subscribeWithPlan` ended in one `.catch(() => 'policy denied')`, so planning and transport failures read as denials. Maintainer rule: "relay-discovery should never be considered a denial. relays can fail from time to time, it's part of nostr."

## Contracts and decisions

- Authority: NAP-OUTBOX draft napplet/naps#32 head `8865f73d52a4864afee145f28d26520476273927` (re-resolved, unchanged). Error Handling codes: `not found`, `no authors`, `relay list unavailable`, `relay timeout`, `policy denied`, `publish denied`, `invalid filter`. Partial relay failure SHOULD set `incomplete: true` and still return events. Shell Behavior: SHOULD fall back to configured relays when NIP-65 data is unreachable; fallback never substitutes for a `toInboxes` read relay.
- NAP-RELAY napplet/naps#2 head `9f30b3505335a52c574ff570576687d6467021ff`: `relay.closed.reason` and `error` are free-form.
- Chosen: planning failure -> `relay list unavailable` (or the network reason the router names); approval not executed -> `policy denied`; transport throw inside the approved callback -> network reason; loader failure -> fallback plan.
- Kept as `policy denied`: unplannable router under approvals (shell fail-closed policy, the draft has no "unsupported" code), abort/revocation, relay gate refusing every required inbox relay.
- Spec gap: no code for "no relay reachable" / "every relay refused". Closest codes: `relay list unavailable` / `relay timeout`. No new code.
