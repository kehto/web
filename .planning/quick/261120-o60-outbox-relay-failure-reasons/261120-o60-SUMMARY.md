# Summary

Relay failures no longer reach napplets as `policy denied`.

- `packages/services/src/outbox-reasons.ts`: NAP-OUTBOX reason constants and the failure-to-reason mapping (spec-gap note).
- `packages/services/src/outbox-approved.ts`: plan / approve / execute split for getEvent, query, subscribe, publish. Late cancellation releases an opened stream; a stream the router closes while opening is not re-registered.
- `packages/services/src/relay-pool-outbox-planned.ts`: planned reads settle on EOSE, skip a relay whose subscribe throws, mark partial results `incomplete`; planned subscriptions survive one failed relay; planned publish labels empty plan / signer refusal / relay failure.
- `packages/services/src/relay-pool-outbox-planning.ts`: a throwing or rejecting NIP-65 loader degrades to missing authors and fallback.
- `packages/services/src/relay-pool-outbox-router.ts`: legacy publish with no accepting relay is `relay timeout`, not `publish denied`.
- `packages/runtime/src/relay-handler.ts`: relay transport throws keep a transport reason.
- `packages/paja/src/browser-relay-runtime.ts`: `publishToRelays` rejects with `publish denied` when the user declines.

Sites checked with no change: `relay-pool-service.ts`, `coordinated-relay.ts`, `count-service.ts` (execute throw -> `count-unavailable`), Paja `browser-social-cache.ts` / `browser-blossom-events.ts` (pass-through), Paja message log (renders wire envelopes verbatim), `@kehto/mocks` outbox line 333 (capability revoke, a real denial).
