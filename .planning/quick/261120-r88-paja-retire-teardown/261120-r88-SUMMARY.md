# Summary: Paja retire goes through revokeNapplet

Finding: the shell's `admitBrowserDocument` retire already destroyed the runtime window (services got
`onWindowDestroyed`) and removed the session before calling Paja's `onRetire`. What leaked was the
bridge's per-window state: transport port binding, cached shell environment and session registration
(`isDomainAllowed` kept answering for the dead id), the nested-context lock flag, and the revoke hook
(so Paja's `readyWindowIds` kept the id).

Fix: `onRetire` calls `bridge.revokeNapplet(windowId, 'host')` on every Paja launch path. Host
retires log as `paja.napplet.retired`.

Out of scope: services can still see `onWindowDestroyed` twice per retire when permissions are on
(`destroyWindow` and `sessionRegistry.unregister` both notify); that predates this change.
