## Authority and resolved decision

Protocol authority is merged
`napplet/naps@5ac0490461ca6fec2f0d2e45b4835cf9bc08de24/naps/NAP-INC.md`
(including merged PRs #89, #90, and #92).

- Lines 333-335 require the binding to retain every materialized inbound handle
  until at least one `channel.onOpened` handler receives it.
- Lines 341-343 allow bounded buffers only when overflow closes and notifies
  instead of silently dropping lifecycle state.
- Line 351 expressly permits a maximum number of concurrent channels per
  napplet, and lines 380-381 recommend rate-limiting opens and bounding resources
  per napplet.

Therefore Plan 102-13's one-slot terminal handoff is superseded. The runtime
will admit no more than 32 live channels for either authenticated endpoint.
Because only the trusted parent can produce `inc.channel.opened`, every
legitimate binding-side opened-handle set is already bounded at 32. The binding
can and must retain all of those pushes without a second local overflow policy.

## Trust Boundaries

| Boundary | Description |
|---|---|
| untrusted napplet → authenticated runtime | Caller asks to open a dTag-targeted channel; runtime identity, session, ACL, and live membership state govern admission. |
| trusted runtime → injected prelude | Only parent-authenticated lifecycle pushes can create napplet-visible inbound handles. |
| retained handle → late napplet callback | Host-owned state is exposed later without changing channel membership or authority. |
